# 블록핏

로블록스 옷(셔츠, 바지, 티셔츠) 파일을 올리기 전에 검사하는 비공식 도구.

로블록스는 옷을 제출할 때마다 로벅스를 받는다. 크기나 형식이 틀린 파일을
올리면 로벅스만 쓰고 원하는 모습이 안 나온다. 그걸 미리 걸러내는 게 목적이다.

## 다루는 범위

그림으로 만드는 2D 옷(셔츠, 바지, 티셔츠)만 다룬다.
날개, 모자, 머리카락 같은 액세서리와 입체(레이어드) 옷은 3D 프로그램으로 만드는 모델이라
검사 방식이 완전히 다르다(삼각형 수, 한 덩어리 여부, 텍스처 크기, 체형별 크기 제한 등).
주 사용자인 초등학생이 실제로 만드는 건 2D 옷이라 2D를 먼저 완성한다.
3D는 나중에 "3D 파일 기본 검사 → 모형에 붙여보기" 순서로 붙일 수 있다.
three.js가 이미 들어가 있어서 3D 파일을 읽는 것 자체는 어렵지 않다.

탭 이름은 공식 이름(셔츠, 바지, 티셔츠)을 쓰고 쉬운 이름(상의 그림, 하의 그림, 가슴 그림)을 붙인다.
"상의", "하의"만 쓰면 3D 입체 옷과 헷갈린다.

## 원칙

- **로그인을 받지 않는다.** 로블록스 관련 사기 사이트는 대부분 로그인을 요구해
  계정을 훔친다. 받지 않는 것 자체가 신뢰의 근거다.
- **파일을 서버로 보내지 않는다.** 모든 검사는 브라우저 안에서 끝난다.
  서버 비용이 없고, 남의 파일을 보관할 책임도 없다.
- **공식 규정보다 엄격하게 굴지 않는다.** 공식 문서가 허용하는 것(예: JPG)을
  "문제"로 표시하지 않는다. 확실히 잘못된 것만 "문제", 결과가 의도와 다를 수
  있는 것은 "주의"로 둔다.
- **저작권 있는 도안을 제공하지 않는다.** 브랜드 로고나 캐릭터 템플릿은 넣지 않는다.
- **로블록스를 브랜드처럼 쓰지 않는다.** 비공식 도구라는 표시를 항상 둔다.
- 사용자 상당수가 어리다. 회원가입을 받지 않아서 개인정보 문제를 원천적으로 피한다.

## 여러 옷 겹쳐 입기

로블록스는 한 캐릭터에 셔츠, 바지, 티셔츠를 동시에 입힐 수 있다.
그래서 옷마다 칸을 따로 두고 각각 파일을 올려 따로 검사한다.
모형에는 올린 옷을 전부 겹쳐 입힌다. 몸통은 아래부터 바지 → 셔츠 → 티셔츠 순서로 덮고,
셔츠에서 비워둔 곳으로는 아래 바지가 보인다. 팔은 셔츠만, 다리는 바지만 입는다.

이 규칙은 `src/lib/outfit.ts` 한 곳에 있고, 3D 모형과 대체용 앞/뒤 그림이 같이 쓴다.

## 출시 전에 채울 것

`src/config/site.ts`의 `OPERATOR`에 운영자 이름과 문의 이메일을 넣는다.
개인정보처리방침과 바닥글의 "문의하기"에 쓰인다. 비어 있으면 연락처 대신 "준비 중"이 나간다.

## 개인정보처리방침

`/privacy`. 실제로 하는 것만 적었다(회원가입 없음, 그림 전송 없음, 쿠키 없음,
꾸민 인원 장난 방지용 해시 값 1시간 보관, 호스팅 접속 기록, 기기 저장소의 "이미 셌음" 표시).
광고나 분석 도구를 붙이는 등 **기능이 바뀌면 방침도 같이 고치고** `PRIVACY_EFFECTIVE_DATE`를 바꾼다.

## 링크 카드 (카톡 미리보기)

`src/app/opengraph-image.png`(1200 × 630)를 Next.js가 자동으로 링크 카드 그림으로 쓴다.
한글 글꼴이 깨질 위험을 없애려고 서버에서 매번 그리지 않고 미리 만든 그림을 둔다.
사이트 주소는 Vercel이 알려주는 대표 주소를 자동으로 쓰고, 도메인을 사면
환경변수 `NEXT_PUBLIC_SITE_URL`에 그 주소를 넣는다.

카톡은 링크 카드를 한동안 저장해둔다. 그림이나 제목을 바꿨는데 예전 카드가 나오면
카카오 개발자 사이트의 공유 디버거에서 해당 주소의 캐시를 지운다.

## 너무 큰 파일

그림을 열기 전에 파일 머리만 읽어서 가로세로를 확인한다(`readDimensions`, PNG·JPG·WebP).
2400만 화소 사진 같은 걸 통째로 열면 오래된 기기가 멈출 수 있어서, 기준을 넘으면 열지 않고 알려준다.
기준은 `src/config/site.ts`의 `MAX_FILE_BYTES`(용량), `MAX_DECODE_PIXELS`(화소 수).

## 결과 한 줄

휴대폰에서는 검사 결과가 3D 모형 아래라 한참 내려야 보인다.
초록 판 바로 아래에 결과를 한 줄로 요약하고 "결과 보러 가기"를 둔다(`MatStatus.tsx`).

## 자동으로 고치기

확실하게 고칠 수 있는 것만 고친다. 로직은 `src/lib/autoFix.ts`.

- 옷 본을 정확히 2배, 3배로 키워 그린 경우: 585 × 559로 줄인다
- PNG가 아닌 파일(JPG, WebP 등): 그림은 그대로 두고 PNG로 다시 저장한다
- 직사각형 티셔츠: 늘리거나 자르지 않고 투명한 정사각형 가운데에 놓는다

크기가 애매하게 다른 셔츠·바지는 고치지 않는다. 억지로 맞추면 칸 위치가 어긋난다.
고친 파일은 같은 칸에 다시 올라가 재검사되고, "고친 파일 받기"로 내려받는다.

## 한국어 옷 본

칸마다 "몸통 / 앞면", "오른팔 / 오른쪽 면"이 한글로 적힌 옷 본을 내려받는다.
공식 옷 본 그림을 베끼지 않고, 칸 위치 숫자만으로 브라우저에서 새로 그린다(`src/lib/templateImage.ts`).
칸 바깥 빈 구석에 "저장 전에 이 층을 숨기세요" 안내와 사이트 주소를 넣는다.
칸 바깥은 게임에서 보이지 않아 옷에 영향이 없다.

## 친구에게 보여주기

옷 입힌 모형 사진과 사이트 주소를 함께 보낸다(`src/lib/shareCard.ts`).
링크로 옷을 보여주려면 그림을 서버에 보관해야 해서 하지 않는다.
사진은 기기 안에서 만들고, 사진 아래에 사이트 주소를 크게 넣는다.
휴대폰에서는 기기의 공유 창을 열고, 안 되는 환경에서는 사진을 저장하고 주소를 복사한다.
주소는 접속한 사이트 주소를 그대로 쓰므로 도메인을 바꿔도 코드를 고칠 필요가 없다.

## 피부색

회색 모형과 여러 피부색 중에서 고른다(`src/config/avatar.ts`). 옷에서 비워둔 곳으로 이 색이 보인다.

## 꾸민 인원 세기

첫 화면에 "현재까지 아바타를 꾸민 인원"을 보여준다.
모형에 처음으로 옷이 입혀지는 순간, 한 기기에서 한 번만 센다.

- 보내는 건 "숫자 하나 올려주세요" 요청뿐이다. 그림이나 개인정보는 보내지 않는다.
- 기기 단위라 대략적인 값이다. 휴대폰과 컴퓨터로 하면 두 번, 브라우저 기록을 지우면 다시 센다.
- 숫자를 부풀리는 장난을 막으려고 같은 곳에서 1시간에 60번까지만 센다.
  IP는 저장하지 않고 해시로 바꾼 값을 1시간만 쓴다.
- 저장소가 연결되지 않으면 숫자만 숨기고 나머지는 정상 작동한다.
- 보여주기 시작하는 최소 숫자는 `src/config/site.ts`의 `COUNTER_MIN_TO_SHOW`.

### 연결 방법

1. Vercel 프로젝트 > **Storage** > **Create Database** > **Upstash for Redis**(Redis)
2. 무료 요금제로 만들고 이 프로젝트에 **Connect**
3. 접속 정보(환경변수)가 자동으로 들어간다. **다시 배포(Redeploy)** 해야 적용된다
4. 로컬에서 확인하려면 `vercel env pull .env.local`.
   직접 넣는다면 `KV_REST_API_URL`, `KV_REST_API_TOKEN`
   (또는 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`)을 `.env.local`에 적는다

## 좌표 검증

`src/config/clothing.ts`의 패널 좌표는 공식 문서에 숫자로 나와 있지 않다.
좌표가 틀리면 미리보기와 "비어 있는 패널" 검사가 엉뚱하게 나온다.

**2026년 10월 검증 완료.** 공식 템플릿 zip의 셔츠·바지 PNG에서 칸마다 칠해진 색 영역을
픽셀 단위로 재서 36칸 모두 x, y, 가로, 세로가 정확히 일치함을 확인했다.
칸 이름(FRONT/BACK/R/L/U/D/F/B)도 같은 자리이고, 3D 모형의 면 방향도
three.js 상자 규칙과 맞물린다(오른팔이 -x, 앞면 오른쪽 끝이 모형의 왼쪽 면과 이어짐).

로블록스가 템플릿을 바꾸면 아래 순서로 다시 확인한다.

1. [공식 문서](https://create.roblox.com/docs/avatar/classic-clothing)에서
   템플릿 zip을 받아 압축을 푼다.
2. `npm run dev`로 띄우고 옷 종류를 "셔츠"로 둔 채 공식 셔츠 템플릿 PNG를 넣는다.
3. "칸 선 보기"를 켠다.
4. 노란 점선 칸이 템플릿에 인쇄된 칸과 **정확히** 겹치는지 본다.
5. 칸 이름도 맞는지 본다. 템플릿에 인쇄된 FRONT/BACK/R/L/U/D/F/B와
   노란 칸의 "앞/뒤/오/왼/위/밑"이 같은 자리여야 한다.
   특히 아래 왼쪽 묶음이 오른팔(R 팔)인지 확인한다.
6. 바지 템플릿으로도 같은 확인을 한다.
7. **왼쪽·오른쪽 확인**: 오른팔 칸에만 빨간색을 칠한 시험 파일을 만들어 넣고,
   3D 모형을 앞에서 봤을 때 빨간 팔이 **화면 왼쪽**(모형의 오른쪽)에 오는지 본다.
   "오른쪽" 버튼을 누르면 빨간 팔의 R 면이 정면으로 보여야 한다.
   반대로 나오면 `AvatarPreview.tsx`의 `rightArm`/`leftArm` 대응을 바꾼다.
8. 칸이 어긋나면 `PANELS` 배열의 x, y 값만 고친다. 다른 파일은 손대지 않아도 된다.

## 규정이 바뀌면

로블록스는 업로드 비용과 조건을 자주 바꾼다(2026년 7월에도 크게 바뀌었다).
비용, 확인 날짜, 규격은 전부 `src/config/clothing.ts` 한 곳에 있다.
바뀌면 여기만 고치고 `UPLOAD_INFO.checkedAt`도 갱신한다.

## 실행

```bash
npm install
npm run dev
npm run build      # push 전에 꼭 확인
npm run typecheck
```

DB가 필요 없다. 꾸민 인원 숫자만 Upstash Redis를 쓰고, 연결하지 않아도 사이트는 정상 작동한다.

3D 모형은 three.js를 쓴다. 무거워서 첫 화면과 따로 불러오고(`next/dynamic`),
3D를 쓸 수 없는 기기에서는 앞/뒤 그림으로 자동으로 바뀐다.
모형은 얼굴 없는 회색 상자로만 만든다. 특정 게임 캐릭터의 모습을 따라 그리지 않는다.
